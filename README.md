## Questionário

### 1. Qual é a diferença entre Working Directory, Staging Area e Repository?

O Working Directory é o local onde os arquivos do projeto são criados e modificados.

A Staging Area é a área intermediária onde os arquivos são preparados para serem incluídos no próximo commit.

O Repository é onde ficam armazenados os commits e o histórico de versões do projeto.

### 2. Qual é a diferença entre git commit e git push?

O git commit registra as alterações no repositório local, criando um novo ponto na história do projeto.

O git push envia os commits do repositório local para o repositório remoto, como o GitHub.

### 3. É possível realizar vários commits antes de executar um git push? Explique.

Sim. É possível realizar vários commits localmente antes de executar o git push.

Cada commit fica registrado no repositório local. Quando o git push é executado, os commits que ainda não estão no repositório remoto são enviados para o GitHub.

### 4. Por que é interessante realizar commits pequenos e descritivos?

Commits pequenos e descritivos facilitam a organização e o acompanhamento do desenvolvimento.

Eles permitem identificar com mais facilidade o que foi alterado em cada etapa e facilitam a consulta ao histórico do projeto.

### 5. O que acontece com os commits locais quando ainda não executamos o git push?

Os commits permanecem armazenados no repositório local.

Eles ainda não estão disponíveis no repositório remoto do GitHub. Quando o git push for executado, os commits pendentes poderão ser enviados para o repositório remoto.

### 6. Como verificar, pelo GitHub, se os commits foram enviados corretamente?

É possível acessar a página do repositório no GitHub e consultar o histórico de commits.

Também é possível comparar a quantidade e as mensagens dos commits exibidos no GitHub com os commits existentes no repositório local.
